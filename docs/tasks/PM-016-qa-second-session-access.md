# PM-016 — Второй независимый сеанс для переписки

**Title:** обеспечить два одновременно различимых тестовых сеанса для [PM-003](PM-003-contact-acceptance.md) и auth QA [PM-010](PM-010-auth-routes-extraction.md).
**Status:** in review — независимые `qa`/`lelik` входы и A→B→A были live-подтверждены, но после block QA основной origin показывает `qa`; пара осталась заблокирована, повторное управление требует входа владельца. **Priority:** P1. **Owner:** Борис / QA.
**Agent:** Борис. **Role:** QA. **Scope:** доступ к двум участникам и пользовательский прогон; без управления реальными чужими учётными записями.
**Recommended model:** Sol. **Recommended reasoning:** Medium. **Reason:** важно не спутать гостя и владельца, права/состояние диалога и сессионный logout.
**Model check:** при возобновлении.

## Goal
Борис самостоятельно управляет двумя одновременно авторизованными PARROT-сеансами и проходит гость → первое сообщение → ответ владельца → возврат без постоянных действий Алексея.

## Problem
В одном браузерном профиле вкладки делят сессию. Переключение аккаунта выкидывает из первого участника; ранее подготовленные два аккаунта сами по себе не означают два доступных сеанса. Существующий CHECK-H11 остаётся без полного обмена.

## Requirements
- Обеспечить второй доступный Борису session state: отдельный браузерный профиль или второй origin согласно [PM-029](PM-029-two-origin-qa-sessions.md). После разового безопасного входа оба участника должны управляться Борисом без переключения Алексея. Не передавать пароль в чат или репозиторий.
- Owner-assisted действия Алексея на iPhone Safari учитываются как частичный QA, но не снимают блокировку самостоятельного двухаккаунтного прогона.
- Борис сверяет роль каждого участника и выполняет PM-003, фиксируя отдельно доступные проверки PM-010.
- Если только один сеанс доступен, провести независимые односторонние проверки и отметить остальное blocked.

## Acceptance criteria
- [ ] Борису одновременно видны и доступны для управления два разных браузера/профиля с разными PARROT-аккаунтами, без смешения cookies и без участия Алексея после первоначального входа.
- [ ] PM-003 получает реальные сообщения и ответ с evidence; результаты auth UI PM-010 отделены от CI разработчика.
- [ ] После теста известны состояние opt-in и остаток тестовых данных.

## Not doing
Создавать дополнительные реальные аккаунты без необходимости, публиковать пароли/токены/тексты сообщений, считать тесты разработчика независимой приёмкой.

## Dependencies / Unblock
Два разрешённых тестовых аккаунта и второй управляемый Борисом браузерный контекст либо независимые сессии на двух origin в одном Cloud Chrome согласно [PM-029](PM-029-two-origin-qa-sessions.md). Owner-assisted Safari позволяет выполнить часть PM-024, но не снимает блокировку PM-003 на самостоятельный полный цикл; PM-010 остаётся in review с доступными односторонними проверками.

## Evidence

- 2026-09-25 — Live Cloud Chrome: `parrot669.cheltsov112.workers.dev` под `qa` и `parrot669.com` под `lelik`. Подтверждены одновременно разные аккаунты, search → обращение → inbox → ответ → возврат, refresh обеих вкладок и сохранение раздельных логинов. Logout `qa` не повлиял на `lelik`; после этого `qa` восстановлен, оба сеанса активны. В одном QA-диалоге остались одно тестовое сообщение и ответ; доступный период на QA-объекте не менялся. Полный перечень и ограничения — [PM-029](PM-029-two-origin-qa-sessions.md).


- 2026-09-25: доступный Борису browser API вернул ровно один браузер: `[{id: "2", name: "Chrome", type: "cdp"}]`. Встроенный Desktop browser (`iab`) и браузер через Chrome extension не представлены. Новые вкладки этого Chrome делят один профиль и не дают второй вход.
- В этом Cloud Chrome PARROT показывает аккаунт `lelik`. Алексей отдельно работает в iPhone Safari под `lelik112`; его Safari не управляется Борисом. Два аккаунта на разных устройствах не доказывают возможность Бориса выполнять обе стороны диалога самостоятельно.
- Появление предыдущего диалога у `lelik112` подтверждалось Алексеем после сообщения аккаунта Минкс в его приватном Safari, а не после сообщения из Cloud Chrome. Позднее Борис отправил отдельное тестовое сообщение из Cloud Chrome `lelik` на объект `The therd`; получение на стороне `lelik112` и ответ ещё не подтверждены.
- Официальная документация описывает отдельное браузерное состояние [Cloud Browser](https://help.openai.com/en/articles/20001280-using-cloud-browser-in-chatgpt) и [ChatGPT Desktop built-in browser](https://help.openai.com/en/articles/20001277-using-the-built-in-browser-in-the-chatgpt-desktop-app), но подключение второго браузера к этой сессии пока не наблюдалось.
- [PM-003](PM-003-contact-acceptance.md), [QA CHECK-H11](../qa/2026-09-23/PARROT669-QA-2026-09-23.md): полный самостоятельный обмен остаётся открытым.
