# PM-016 — Второй независимый сеанс для переписки

**Title:** обеспечить два одновременно различимых тестовых сеанса для [PM-003](PM-003-contact-acceptance.md) и auth QA [PM-010](PM-010-auth-routes-extraction.md).
**Status:** in review — одновременные сессии на iPhone Safari и Cloud Chrome подтверждены для разных аккаунтов; явный logout-isolation test не выполнялся. **Priority:** P1. **Owner:** Борис / QA; owner-assisted действия на локальном устройстве — Алексей.
**Agent:** Борис. **Role:** QA. **Scope:** доступ к двум участникам и пользовательский прогон; без управления реальными чужими учётными записями.
**Recommended model:** Sol. **Recommended reasoning:** Medium. **Reason:** важно не спутать гостя и владельца, права/состояние диалога и сессионный logout.
**Model check:** при возобновлении.

## Goal
Независимо пройти гость → первое сообщение → ответ владельца → возврат и проверить auth переходы.

## Problem
В одном браузерном профиле вкладки делят сессию. Переключение аккаунта выкидывает из первого участника; ранее подготовленные два аккаунта сами по себе не означают два доступных сеанса. Существующий CHECK-H11 остаётся без полного обмена.

## Requirements
- Предоставить второй независимый браузерный сеанс/профиль с разрешённым тестовым аккаунтом или синхронное участие Алексея со второго аккаунта. Не передавать пароль в репозиторий.
- Борис сверяет роль каждого участника и выполняет PM-003, фиксируя отдельно доступные проверки PM-010.
- Если только один сеанс доступен, провести независимые односторонние проверки и отметить остальное blocked.

## Acceptance criteria
- [ ] Два участника подтверждены разными сеансами, без смешения cookies.
- [ ] PM-003 получает реальные сообщения и ответ с evidence; результаты auth UI PM-010 отделены от CI разработчика.
- [ ] После теста известны состояние opt-in и остаток тестовых данных.

## Not doing
Создавать дополнительные реальные аккаунты без необходимости, публиковать пароли/токены/тексты сообщений, считать тесты разработчика независимой приёмкой.

## Dependencies / Unblock
Два ранее подготовленных тестовых аккаунта и доступный второй изолированный сеанс или участие Алексея; сейчас его VPN может мешать синхронным действиям. PM-003 уже blocked по доступу, PM-010 остаётся in review и допускает односторонний QA.
