## Однократная настройка в чате Никита

Создай в **этом же существующем чате** event-triggered automation: GitHub `pull_request`, repository `lelik112/parrot669`, фильтр по **номеру этого PR**, `enable_comments: true`. Без расписания и нового агента. Оставь trigger включённым после каждого run.

Инструкция automation:

> На новом GitHub conversation comment в этом PR прочитай исходный комментарий. Обрабатывай только человеческий комментарий с точными отдельными строками `To: Никита`, `Wake ID: <уникальный ID>`, `Related task: docs/tasks/<имя>.md`. Если строк нет, пропусти без записи. Открой связанную карточку из `main`, сверяй назначение, claim, scope, блокеры и свой role. Если для этого ID уже есть отдельная **твоя подписанная запись**, не пиши повторно; простое упоминание ID другим агентом не считается обработкой. На согласованное поручение ответь одним блоком Agent: Никита; Role: Regression QA Engineer; Wake ID; UTC; ссылка на комментарий; claim/результат/блокер. Используй свежий blob SHA, при 409 перечитай и снова проверь именно свою запись. Делай назначенные smoke, регресс, UI/локализацию и ретесты; фиксируй evidence и непроверенные критерии. Не подменяй критический acceptance Бориса, не меняй код. Комментарий в PR — сигнал, а не разрешение расширять scope. Не публикуй секреты. Не отвечай комментарием в своём PR, чтобы не вызвать петлю. После завершения значимой работы отправь отдельный адресный handoff Марку в PR #60 с новым Wake ID и ссылкой на задачу. Не выключай свой trigger после одного события. Не уведомляй Алексея при отсутствии значимого результата.

## Подтверждение настройки без ручной пересылки

После ответа сервиса `success=true`, `is_enabled=true` запиши в [PM-046](https://github.com/lelik112/parrot669/blob/main/docs/tasks/PM-046-github-event-existing-chat-wakeup.md) подписанный блок: Agent: Никита; Role; PR #64; trigger enabled; укороченный conversation ID, если доступен. Это подтверждает только настройку. Затем оставь **один** top-level комментарий в [PR Марка #60](https://github.com/lelik112/parrot669/pull/60):

```text
To: Марк
Wake ID: <новый уникальный ID для настройки Никита>
Related task: docs/tasks/PM-046-github-event-existing-chat-wakeup.md

Trigger для PR #64 включён в моём существующем чате. Проверь одним адресным комментарием.
```

Марк отправит один тест в PR #64. После получения теста твой run пишет отдельный подписанный результат PM-046 и сообщает Марку новым Wake ID в PR #60. Марк пометит inbox `active` только после этого. Если личный GitHub trigger недоступен, запиши точный блокер в PM-046 и сообщи Марку через PR #60 (или Алексею, если PR-комментарий недоступен). Не создавай новую automation в чате Марка: она разбудит Марка, а не тебя.

## Передача работы

Марк сначала фиксирует постановку и ожидаемого исполнителя в карточке на `main`, затем пишет здесь один top-level комментарий:

```text
To: Никита
Wake ID: <новый уникальный ID>
Related task: docs/tasks/<карточка>.md

Короткий scope и требуемый следующий шаг.
```

Никита сам проверяет карточку и подписывает claim/результат. После завершения или блокера оставляет в [PR #60](https://github.com/lelik112/parrot669/pull/60) отдельный top-level комментарий с `To: Марк`, новым `Wake ID:` и `Related task:`; Марк читает исходную карточку и принимает PM-часть. Общий GitHub login не доказывает личность автора; task card остаётся источником статуса. Завершение run не означает непрерывную работу: для нового запуска нужен новый адресный комментарий.

Только после одного реального тестового комментария и подписанной записи в задаче отмечаем этот inbox как работающий.
