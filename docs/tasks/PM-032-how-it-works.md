# PM-032 — Как работает PARROT для гостя и хозяина

**Title:** подготовить два коротких сценария How it works по фактическому MVP.
**Status:** planned — LATER после PM-031 и основных QA результатов. **Priority:** later. **Owner:** Марк / Product Manager для редакционного контракта; активного claim нет.
**Agent:** будущий исполнитель продуктового текста. **Role:** Product Manager. **Scope:** документация и сценарии; без сайта и новой фичи.
**Recommended model:** Luna. **Recommended reasoning:** Medium. **Reason:** два коротких объяснения, но нужно точно сверить опубликованные и проверенные шаги.

## Goal
Новый гость и хозяин быстро понимают путь к результату.

## Problem
Нынешняя главная рассказывает о старых локальных услугах; полезный путь жилья находится глубже, а готовые объяснения поиска и контакта не согласованы.

## User
Гость, которому нужно жильё на даты, и хозяин, который хочет опубликовать доступность.

## Value
Меньше ложных ожиданий при входе и понятный следующий шаг для обеих сторон.

## Solution
Два компактных сценария для будущей страницы: гость — выбрать страну/город и даты → оценить доступность/источник/цену → открыть объект и написать хозяину; хозяин — войти → добавить объект и периоды → при желании подключить iCal/опубликовать внешний линк → ответить в Messages. Текст отделяет подтверждённые сценарии от неподтверждённых QA.

## Alternatives
Оставить старую маркетинговую главную; написать подробный гид до завершения QA.

## Rejected
Описание бронирования/оплаты в PARROT, обязательного Airbnb, гарантии ответа хозяина или готового публичного профиля до его релиза.

## Requirements
- Сверить итог PM-024/023/003, PM-001/002 и словарь PM-031; отметить незавершённый QA.
- Дать по одному краткому сценарию и явный CTA для гостя и хозяина; без обещания несуществующих полей/статусов.
- Указать, что связь идёт через PARROT, условия аренды согласуются с владельцем/внешней площадкой.
- Предложить размещение относительно поиска и host entry, но homepage менять отдельной задачей после approval.

## Acceptance criteria
- [ ] Оба сценария соответствуют текущему product-context и результатам QA.
- [ ] Гость видит путь «даты → жильё → контакт», хозяин — «объект → доступность → ответ».
- [ ] Текст не обещает бронирование, проверку личности или готовый публичный профиль.
- [ ] Владелец утвердил текст и место использования до реализации.

## Not doing
Вёрстка homepage, UI-код, отдельная система обучения или перенос старых услуг.

## Dependencies
PM-031 и первая QA-волна PM-024/023/003; PM-022 только если профиль фактически выпущен.

## Success criteria
Пользователь после чтения знает первое действие и что произойдёт после нажатия «Написать владельцу».
