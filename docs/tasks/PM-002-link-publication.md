# PM-002 — Правило публикации внешней ссылки

**Title:** согласовать и реализовать публикацию Airbnb-ссылки после проверки источника.

**Status:** blocked — product decision. **Priority:** P1. **Owner:** исполнитель не заявлен; обсуждение ведёт Марк / PM.

**Area:** свойства внешнего объявления, поиск, согласованные публичные страницы. **Source:** PRODUCT-001.

**Product decision:** [D003 proposed](../decisions/D003-link-publication-proposal.md). **Updated:** 2026-09-24.

## Goal

Одинаковое и понятное правило показа ссылки во всех согласованных точках продукта.

## Problem

Галка сейчас включена по умолчанию и независима от проверки. Владелец хочет ограничить её до подтверждения; полное новое правило ещё не записано. Это изменение контракта, не нарушение старой спецификации.

## Context

[QA PRODUCT-001](../qa/2026-09-24/PARROT669-QA-HOST-2026-09-24.md). Поиск и публичный профиль сейчас имеют разные правила видимости. v1 verified не подтверждал выполнение задания D002. Вопрос PM об автоматическом/ручном включении после успеха остаётся без ответа.

## User

Владелец, управляющий публикацией; гость, переходящий во внешнее объявление.

## Value

Связь между конкретным сигналом и разрешённым публичным переходом без потери независимых объектов.

## Solution

Сначала принять [D003](../decisions/D003-link-publication-proposal.md), затем реализовать единый контракт UI/сервер/выдача. Ниже **предлагаемые**, не окончательные требования. До принятия разрешены обсуждение и техническая оценка; реализация нового поведения заблокирована.

## Requirements — proposal

- Новая ссылка скрыта до подходящей проверки текущего источника. Нельзя обойти правило прямым запросом или старым `showInSearch=true`.
- После успеха владелец получает возможность публикации. Автоматическое включение либо отдельная галка выбираются решением; PM рекомендует отдельную галку.
- Описать переход старых опубликованных ссылок и v1 verified. Не приписывать старой проверке новое доказательство.
- Смена/удаление источника прекращает показ, если подтверждение утрачено. Обычный disable/enable сейчас сохраняет verified; не менять это без отдельного решения.
- Объект без опубликованной ссылки остаётся в поиске при подходящей доступности. Приём сообщений и согласие владельца не меняются.
- Область ограничения перечислена явно: поиск, публичный профиль или оба. Тексты не обещают проверку личности/собственности.

## Acceptance criteria

- [ ] Сначала D003 переведено в accepted с ответами на все открытые вопросы; задача переведена из blocked.
- [ ] Таблица ожидаемого показа покрывает отсутствие календаря, required/pending/failed/blocked, подходящее verified, потерю подтверждения и старые данные.
- [ ] В согласованной области UI, серверная запись и публичный ответ следуют одной таблице; только disabled-галка не считается решением.
- [ ] Выбранное действие после успеха реализовано точно; скрытие ссылки не скрывает сам подходящий объект.
- [ ] Изменение/удаление источника и обычный disable/enable дают согласованные результаты.
- [ ] QA проверил публичное поведение и данные старой модели; релиз и ограничения записаны отдельно.

## Alternatives

Оставить независимую ссылку; включать автоматически после успеха; отдельное включение владельцем. Область публичного профиля также обсуждается явно.

## Rejected

Окончательные альтернативы ещё не отклонены. Не принимается UI-only защита и не вводится обязательное Airbnb-объявление для поиска объекта.

## Success criteria

После принятия решения гость не видит ссылку, не соответствующую выбранной политике; владелец понимает, что сделать для публикации. В пилоте оценить потерю доступных каналов контакта.

## Not doing

Проверка личности, скрытие целого объекта по одному отсутствию ссылки, автоматическое согласие на сообщения, переписывание синхронизации.

## Dependencies

D003 accepted; определён смысл проверки PM-001 и политика для старых статусов; один ответственный согласует изменения между backend/frontend. Не пересекаться с изменением календарного flow без записи границ.

## Evidence

Implementation: не начата по этой постановке. QA: отсутствует. Текущее поведение описано в QA, но не считается реализацией нового контракта.
