# PM-031 — Словарь проверяемых фактов PARROT

**Title:** согласовать смысл терминов доступности, внешнего источника и проверок для гостя и владельца.
**Status:** planned — NEXT, продуктовый контракт; разработка не назначена. **Priority:** P2. **Owner:** Марк / Product Manager, без активного claim на отдельную задачу.
**Agent:** Марк / Product Manager для подготовки контракта; **Scope:** продуктовая документация и текстовые правила, без UI-кода.
**Recommended model:** Sol. **Recommended reasoning:** Medium. **Reason:** формулировки связывают доступность, D002/D010/D011, поиск, профиль и FAQ; нет новой технической реализации.

## Goal
Одинаковые слова в поиске, кабинете, профиле и объясняющих материалах означают одинаковые проверяемые факты.

## Problem
«Доступно», «подтверждено», «проверено», «синхронизировано» и «владелец» легко прочесть как обещание бронирования, проверки личности или актуальной внешней доступности, которой PARROT не проводил.

## User
Гость, выбирающий жильё, и хозяин, управляющий объектом и календарём.

## Value
Гость понимает, откуда взялись даты, цену и trust-сигнал; владелец понимает, что именно подтверждает своим действием.

## Solution
Составить таблицу для Available, External listing, Verified email, Calendar control verified, Last synced, Contact host, Price и Minimum stay: точный факт, источник, состояние без данных/устарело/ошибка, короткий UI-текст RU/EN/ES/CA и недопустимый вывод. Отдельно объяснить физическую доступность PARROT и platform-specific Airbnb unavailability; применять D002, D010, D011.

## Alternatives
Отдельный текст на каждом экране; общий рекламный статус доверия.

## Rejected
«Trusted host», обещание фактического права сдавать жильё, гарантии бронирования и вывод о свободных датах только из факта успешной синхронизации.

## Requirements
- Сверить опубликованные статусы поиска, PM-001/002/024, current product-context и реальный guest flow; не переписывать историю решений.
- Для calendar verified указывать только контроль текущего источника по сохранённому заданию; legacy v1, lost/expired/failed не считать этим сигналом.
- Verified email означает контроль адреса почты, а не личности; Last synced означает время получения источника, а не гарантию свободных дат.
- Price — известная оценка полного периода с указанной уборкой; при неполных ночных ценах не показывать оценку. Minimum stay — правило владельца/поиска, не обещание внешней площадки.
- Для отсутствующей/скрытой Airbnb-ссылки использовать нейтральный текст; действие Contact host следует D011 и не обещает ответа.
- Прежде чем менять UI-копию, получить отдельный приоритет и разработческую задачу, если найдётся конкретный дефект.

## Acceptance criteria
- [ ] Таблица терминов и состояний охватывает все восемь понятий, источники и RU/EN/ES/CA.
- [ ] Согласована с D002/D010/D011, product-context и PM-022; нет общего host trust claim.
- [ ] Неясные/противоречивые строки помечены как решения для владельца, а не объявлены опубликованными.
- [ ] PM-032 и PM-033 ссылаются на принятый словарь.

## Not doing
Массовый редизайн, новый бейдж, проверка личности, Airbnb API или реализация копии в приложении.

## Dependencies
PM-001/002 QA для точных календарных состояний; D002/D010/D011 приняты. PM-030 задаёт очередь. Для редакционного контракта не нужна новая QA-сессия.

## Success criteria
В коротком сценарии гость может объяснить, что именно подтверждено и как связаться с хозяином, не делая вывода о гарантии бронирования.
