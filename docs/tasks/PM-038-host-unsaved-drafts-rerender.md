# PM-038 — не терять несохранённые правки в кабинете

**Title:** сохранить или явно подтвердить сброс черновика при смене языка и обновлении dashboard.

**Status:** reported from code / NOW for focused QA; developer claim не заявлен. **Priority:** P2, повысить при подтверждённой потере важных пользовательских данных. **Owner:** Марк / PM (triage). **QA:** Никита / Regression QA — кандидат на короткий независимый ретест, без claim. **Suggested developer:** Денис / Developer после проверки и отдельного claim. **Origin:** [PM-034-FE](PM-034-FE-frontend-audit.md).

**Agent:** Марк. **Role:** Product Manager. **Scope:** продуктовый контракт и acceptance, не реализация.

**Recommended model:** Sol. **Recommended reasoning:** Medium для точечного UI/state исправления. **QA recommendation:** Luna / Medium для воспроизведения desktop/языков. **Reason:** рендер разных host форм и сохранение введённого без смены auth/cookie.

## Goal

Хозяин не теряет введённые, но ещё не сохранённые изменения карточки объекта или своего имени из-за переключения языка либо фонового обновления кабинета.

## Problem / Context

Денис установил по коду, что `host.js applyLanguage → renderProperties` заменяет form nodes и сбрасывает dirty flag. Введение нового имени в профиле перед `syncCalendar → syncDashboard` также может быть перезаписано серверным значением; другие формы пересоздаются. Это **воспроизводимые из control flow гипотезы**, live QA пока не записана. Уход со страницы уже имеет предупреждение о несохранённом, но оно не защищает внутренний rerender. [BUG-022](BUG-022-host-return-loses-scroll-position.md) относится к scroll и не подменяет этот scope.

## Requirements

- Никита или Борис независимо проверяет два случая на безопасном объекте: (1) изменить title/условия без Save → нажать другой язык; (2) изменить displayName или другой property form без Save → запустить безопасный calendar/dashboard refresh. Записать до/после, браузер/язык, затронутые поля; не публиковать личные данные. Не менять реальные календарные брони ради теста.
- После QA dev выбирает самый маленький вариант: сохранять черновик через рендер или спрашивать явное подтверждение сброса там, где сохранение невозможно. Отмена сохраняет ввод; подтверждение сброса ясно сообщает о потере изменений.
- Для асинхронного dashboard refresh успешное обновление другого участка не меняет несохранённые формы; save одной формы очищает только её собственное dirty state. 401/logout сохраняют действующие правила безопасности.
- Проверить все четыре языка, два объекта с независимыми формами, календарный sync/error path и переходы через Host/Search/Messages; не менять auth, URLs, доступность и iCal semantics.

## Acceptance criteria

- [ ] QA фиксирует воспроизведение либо объясняет, почему конкретный кодовый путь не приводит к потере ввода; только затем согласуется scope исправления.
- [ ] Смена языка с dirty полем не стирает его без подтверждения; отмена оставляет введённое и текущую форму, принятие меняет язык согласно выбранному поведению.
- [ ] Dashboard refresh после календарного действия сохраняет незавершённые изменения в профиле и других объектах либо предлагает ясный контролируемый выход.
- [ ] Сохранённые значения после Save/reload прежние; старые предупреждения при навигации и auth/session ветки проходят регресс; есть независимый QA retest.

## Not doing

Перевод всего frontend на framework, переписывание `host.js` целиком, редактирование профиля без согласованного product contract, исправление 5xx empty dashboard в рамках этой задачи. Последняя гипотеза остаётся в [PM-034](PM-034-backend-frontend-refactoring-audit.md) до отдельной QA/приоритизации.
