# BUG-018 — Конечная дата не обновляется после выбора начальной

**Title:** исправить выбор конца диапазона после изменения начальной даты на iPhone Safari.
**Status:** planned — NEXT; исполнитель не назначен, claim отсутствует. **Priority:** P2.
**Owner:** не назначен; сначала сверить пересечение с активной работой в Host/calendar UI. QA: Борис.
**Agent:** будущий Developer. **Role:** Developer. **Scope:** состояние выбора диапазона дат; без изменения календарной верификации или Airbnb sync.
**Recommended model:** Sol. **Recommended reasoning:** Medium. **Reason:** локальный UI-дефект, но требуется сохранить действующую семантику диапазона и воспроизвести поведение в iPhone Safari.

## Goal

После выбора начальной даты пользователь может выбрать корректную конечную дату без лишнего перелистывания календаря и без использования устаревшего значения.

## Problem

Во время owner-assisted проверки PM-001 на iPhone Safari после выбора начальной даты конечная дата не сбросилась к допустимому значению. Чтобы продолжить, пользователю пришлось перелистывать календарь вперёд.

## User

Хозяин, который выбирает даты календарной проверки с телефона.

## Value

Понятный и предсказуемый мобильный ввод дат в основном сценарии проверки календаря.

## Requirements

- Воспроизвести на iPhone Safari после выбора начальной даты; записать версию iOS/Safari и шаги.
- После смены начала конечная дата должна очищаться или обновляться до допустимой по текущему контракту; конечная дата не может оставаться раньше начала.
- Пользователь должен видеть и выбрать следующий допустимый день без перехода через устаревший месяц/дату.
- Проверить, что выбранные обе даты отображаются правильно и передаются в существующее задание PM-001.
- Проверить соответствующее поведение в desktop web и других доступных размерах; не объявлять платформы дефектными без воспроизведения.
- Не менять календарный verification contract, правила допустимости диапазона или iCal synchronization.

## Acceptance criteria

- [ ] Повторный выбор начала на iPhone Safari не оставляет недопустимую конечную дату.
- [ ] Пользователь может выбрать ближайшую допустимую конечную дату без лишнего перелистывания.
- [ ] Сохранённое задание PM-001 содержит выбранный диапазон, а не прежнее конечное значение.
- [ ] Другие проверенные платформы не получили регрессию выбора диапазона.
- [ ] Борис фиксирует результат на реальном устройстве либо явно помечает непроверенную среду.

## Alternatives

Оставить прежнюю конечную дату и заставить пользователя вручную перелистывать календарь; заменить компонент выбора дат целиком.

## Rejected

Переписывание календарной интеграции или синхронизации ради локального UI-состояния; считать баг только мобильным или общим до воспроизведения.

## Dependencies

[PM-001](PM-001-calendar-control-dates.md), [PM-015](PM-015-qa-mobile-device-environment.md). Не менять код в общей Host области без сверки claim PM-021.

## Evidence

Owner-assisted прогон с Борисом: iPhone Safari; после выбора начала диапазона конец не обновился, пришлось перелистывать календарь. Пользователь продолжил сценарий, и проверка календаря завершилась успешно. Полная спецификация устройства/версии Safari пока не записана.
