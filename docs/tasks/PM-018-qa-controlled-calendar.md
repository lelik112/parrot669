# PM-018 — Контролируемый Airbnb-календарь для оставшегося QA

**Title:** обеспечить внешние изменения календаря и отдельные исходные состояния для незакрытых сценариев [PM-001](PM-001-calendar-control-dates.md).
**Status:** blocked — у QA нет управления Airbnb-календарём владельца и отдельного контролируемого источника; текущая попытка 1 из 3 после ретеста PM-013 ожидает без изменения. **Priority:** P1. **Owner:** Борис / QA после разблокировки; внешние действия — Алексей.
**Agent:** Борис. **Role:** QA. **Scope:** подготовка контролируемых календарных сценариев и независимый результат, без исправления backend/frontend.
**Recommended model:** Sol. **Recommended reasoning:** Medium. **Reason:** несколько исходных состояний и расписание повторов требуют точной фиксации времени, источника и очистки.
**Model check:** при возобновлении.

## Goal
Закрыть оставшиеся пользовательские проверки PM-001 без выдуманной доступности или ложного результата.

## Problem
QA может нажимать PARROT, но не меняет Airbnb за владельца. Положительный `open`, смешанные/Reserved ночи и другая сторона PM-013 waiting требуют подготовленного внешнего состояния или отдельного источника. После успешного PM-013 ретеста текущий календарь переподключён и одна попытка ожидает автоматические проверки.

## Requirements
- Алексей согласует и вручную готовит конкретные тестовые ночи в Airbnb или предоставляет отдельный управляемый тестовый iCal; QA заранее фиксирует выбранный диапазон и ожидаемое действие.
- Борис проходит положительный `open`, смешанный/Reserved диапазон и ветку waiting для `close`, сверяя экспорт/проверку только по доступным наблюдениям.
- Остальные негативные/технические границы PM-001 указываются отдельно; после тестов вернуть временные ночи и статус test fixture в явное состояние.
- Не менять реальные брони и не извлекать секретную iCal-ссылку.

## Acceptance criteria
- [ ] Внешнее изменение сделано после сохранённого задания и до доступного Check; положительный `open` проверен.
- [ ] Для исходно свободного диапазона waiting просит закрыть ночи и ждёт автоматически; EN/ES/CA/RU по возможности.
- [ ] Неподходящие исходные состояния отвергнуты до действия владельца; evidence и ограничения записаны в PM-001.
- [ ] Тестовые даты восстановлены и счётчик попыток/подтверждение указаны.

## Not doing
Автоматическое изменение Airbnb, новый backend reset, объявление полной PM-001 приёмки по одному сценарию.

## Dependencies / Unblock
Внешние действия владельца в Airbnb или отдельный безопасный тестовый источник и окно времени для экспортного iCal. PM-001 остаётся in review; автономно доступны обзор UI и проверка других задач.
