# PM-039 — доступная среда для браузерной и мобильной QA

**Title:** выбрать недорогой способ автоматизированной браузерной проверки и независимого ретеста на реальном iPhone Safari.
**Status:** done — Алексей выбрал Playwright для доступного browser QA и отдельную blocked real-device очередь [D016](../decisions/D016-playwright-first-real-device-queue.md); исследование выбора завершено, реализация [PM-040](PM-040-playwright-web-e2e.md) и телефонные проверки [PM-041](PM-041-real-device-qa-queue.md) открыты. **Priority:** P1 (исторический). **Owner:** Марк / Product Manager.

**Agent:** Марк. **Role:** Product Manager. **Scope:** ограничения QA, варианты и стоимость, приоритизация, acceptance и координация; без кода, подписок, настройки аккаунтов или CI.
**Recommended model:** Sol. **Recommended reasoning:** Medium. **Reason:** нужно сопоставить несколько типов сред с фактическими QA-блокерами и текущими ценами, не приравнивая эмуляцию к iPhone Safari.
**Model check — Марк, 2026-09-25:** Sol / Medium достаточно для анализа документации, условий и постановки ограниченного пилота.

## Goal / Problem

Борис проверил существенную часть веб-сценариев, но в текущем управляемом браузере нет настоящего iPhone Safari, touch/экранной клавиатуры и профиля с нативным autofill. Поэтому [PM-015](PM-015-qa-mobile-device-environment.md), [PM-007](PM-007-mobile-acceptance.md), [BUG-018](BUG-018-calendar-end-date-mobile-safari.md) и мобильная часть [PM-025](PM-025-search-contact-button-layout.md) не закрываются независимо. [PM-004](PM-004-street-autofill.md)/[PM-014](PM-014-qa-native-autofill-environment.md) требуют ещё и исходного сохранённого адреса. Сдавать desktop viewport за настоящий iPhone нельзя.

## Requirements

1. Составить проверяемую матрицу: desktop браузеры; мобильный viewport/touch emulation; iOS Simulator Safari; удалённый реальный iPhone Safari с нативной клавиатурой и date picker; профиль Safari со сохранённым адресом. Для каждого вида указать, какие acceptance критерии он закрывает, а какие остаются unverified.
2. Оценить цену по фактическому сценарию PARROT: разовые 15/30/60 минут и 1–2 часа в месяц, сбор скриншотов/видео, доступ Бориса без ручного участия Алексея, безопасный тестовый аккаунт, возможность открыть PARROT с нужного региона/сети. Проверить цену/лимиты непосредственно перед выбором платного сервиса.
3. Первым использовать бесплатную browser emulation для регулярного layout/navigation smoke там, где она отвечает критерию. Для настоящего iPhone Safari рассмотреть короткий поштучный remote-device пилот без годовой подписки; доступ к Cloudflare/Railway, приватным аккаунтам и секретам не расширять ради тестов.
4. Перед покупкой/настройкой внешней среды проверить: независимый доступ Бориса, работу PARROT в выбранном устройстве/сети, сохранение QA двух аккаунтов и сбор evidence. Не переносить в done PM-007/BUG-018 лишь по выбору провайдера.
5. Предложить минимальный пилот и стоимость; затем согласовать отдельное решение владельца о расходах и исполнителе технической настройки. Разработчикам не начинать интеграцию или подписку по одному упоминанию в этой карточке.

## Короткий список, исследование Марка — 2026-09-25

| Вариант | Подтверждённые возможности / цена | Покрытие и ограничения для PARROT |
| --- | --- | --- |
| Playwright локально/в существующем CI: Chromium + WebKit с device emulation | Открытый инструмент; emulation задаёт user agent, viewport, screen size и touch. У Playwright WebKit отдельная сборка, **не фирменный Safari**. Дополнительная подписка на сервис не требуется; стоимость CI/работы по внедрению ещё не оценена. [Emulation](https://playwright.dev/docs/emulation), [Browsers](https://playwright.dev/docs/browsers). | Быстро и воспроизводимо проверяет поиск → CTA, возврат, переполнение, языки на разных ширинах; не принимает нативный iPhone date picker/клавиатуру/autofill BUG-018/PM-014. Разработчику предстоит предложить небольшую smoke-матрицу, код сейчас не поручен. |
| Xcode iOS Simulator + Safari на доступном Mac | Xcode бесплатен в Mac App Store, в нём доступны iOS Simulator и Safari; [Apple docs](https://developer.apple.com/documentation/safari-developer-tools/installing-xcode-and-simulators). | Лучше для iOS UI, но нужен доступ к Mac/симулятору **самому QA**, а не экран Алексея по просьбе. Наличие Mac у владельца не подтверждает, что Борис может самостоятельно управлять сеансом; симулятор не является физическим устройством для окончательного real-device критерия. |
| AWS Device Farm, удалённый реальный iOS Safari | [Цена](https://aws.amazon.com/device-farm/pricing/): разовые 1000 бесплатных device minutes для подходящего нового аккаунта (промо, проверить eligibility), затем $0.17/device-minute, то есть $2.55 за 15 мин, $5.10 за 30 мин, $10.20 за час, $20.40 за 2 часа. [Remote access](https://docs.aws.amazon.com/devicefarm/latest/developerguide/remote-access.html) позволяет ручной сеанс на реальном устройстве через браузер, [AWS FAQ](https://aws.amazon.com/device-farm/faqs/) указывает Safari для web на iOS. | Лучший кандидат для ограниченного независимого QA без телефона владельца, если текущая среда агента может открыть AWS и PARROT. Сеанс/подготовка тарифицируются; перед расходами проверить регион/доступ, возможность задать сохранённый адрес для PM-014 и выделить безопасный тестовый сеанс. Без проверки этих условий **не** считать блокеры снятыми. |
| AWS Device Farm + Appium для автоматизации на физическом iPhone | В той же тарифицируемой remote session доступен [Appium endpoint](https://docs.aws.amazon.com/devicefarm/latest/developerguide/appium-endpoint-interaction.html); web-приложение открывается через `browserName=Safari` на iOS, клиентские сценарии можно повторять в течение сессии. Дополнительную плату за Appium сверх device minutes официальная страница не указывает; настройка и сопровождение тестов — трудозатраты разработчика, не $0. | Потенциально автоматизирует короткий поиск/CTA/переход на настоящем Safari; сначала вручную проверить доступность сайта/тестовых аккаунтов, затем отдельным узким dev claim оценить 2–3 сценария и пригодность нативного picker/autofill. Автотест DOM сам по себе не заменяет визуальный QA Бориса. |
| BrowserStack Live | [Trial](https://www.browserstack.com/support/faq/plans-pricing/plans/what-do-i-get-with-a-free-trial): 30 минут web/browser testing, ограничение 1 минута на доступное устройство; [Live](https://www.browserstack.com/live/) предлагает реальные мобильные браузеры. Актуальную платную цену и помесячные/годовые условия надо подтвердить перед покупкой на [pricing](https://www.browserstack.com/pricing). | Возможная запасная проверка на реальном Safari; пробных минут может не хватить на полный PM-007. Постоянную платную подписку пока не рекомендуем: частота QA/доступность агента не установлены. |

**Исторический предварительный вариант до D016:** бесплатный Playwright для регулярного responsive/smoke; для критериев реального iPhone рассматривался короткий ручной пилот AWS Device Farm, если сайт и агент доступны. При успешном пилоте предложить разработчику отдельный небольшой Appium smoke на реальном Safari с оценкой трудозатрат и измеренных device minutes, без автоматического запуска на каждый commit. Целевая дополнительная стоимость на старте: $0 подписки, для часа вне бесплатного trial около $10.20, два часа около $20.40 (фактическая стоимость зависит от тарифицируемых device minutes). Это **рекомендация**, не купленный сервис, не подтверждённая работоспособность и не согласованный бюджет.
