# PM-036 — Agent Scheduler Check-in

**Title:** автоматическая проверка задач агентами без ручного переключения чатов.

**Status:** planned. **Priority:** P2. **Owner:** Марк / Product Manager.

**Agent:** Марк. **Role:** Product Manager. **Scope:** процесс команды и orchestration; без реализации инфраструктуры агентов на этом этапе.

**Recommended model:** Sol. **Recommended reasoning:** Medium.

**Reason:** требуется спроектировать процесс распределения задач между несколькими AI-агентами, сохранив текущую модель claims, owners и единого источника состояния в репозитории.

## Goal

Убрать необходимость ручного переключения Алексея между чатами агентов.

Агенты должны самостоятельно периодически проверять назначенные им задачи и забирать работу после назначения Марком.

## Problem

Сейчас процесс:

Алексей → чат агента → задача → работа.

При росте команды это создаёт ручную диспетчеризацию.

Нужно перейти к модели:

Марк → task assignment → repository state → agent check-in → claim → работа.

## Requirements

Разработать предложение процесса:

- где хранится назначение задачи;
- как агент понимает, что задача ему назначена;
- как часто выполняется check-in;
- как избежать параллельного взятия одной задачи;
- как работает claim;
- как обрабатываются blocked/in review/done задачи.

Рассмотреть модель:

- периодический дешёвый check без запуска полного reasoning;
- запуск полноценной сессии только при наличии изменений.

## Constraints

Не создавать:

- автоматический хаотичный запуск агентов;
- несколько владельцев одной задачи;
- обход существующей модели PM/claims.

Марк остаётся владельцем назначения и приоритетов.
