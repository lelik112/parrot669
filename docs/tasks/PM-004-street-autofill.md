# PM-004 — Подсказки улиц без перекрытия

**Title:** устранить конкуренцию браузерного autofill и выбора улицы PARROT.

**Status:** blocked — доступный desktop Chrome partial PASS, но исходный конфликт нативного сохранённого адреса не воспроизведён; ждёт [PM-014](PM-014-qa-native-autofill-environment.md). Мобильный touch дополнительно зависит от [PM-015](PM-015-qa-mobile-device-environment.md); [PM-039](PM-039-browser-test-environments.md) проверит пригодность удалённого Safari с сохранённым адресом. **Priority:** P2. **Owner:** Денис / Developer.

**Agent (следующий шаг):** Борис / QA; claim ожидается. **Recommended model:** Luna. **Recommended reasoning:** Low. **Reason:** ближайшая проверка ограничена нативным browser autofill и зафиксированными desktop/mobile criteria; если нельзя воспроизвести сохранённый адрес/Safari, результат помечается непроверенным, а не выводится из тестовых событий.

**Model check:** Борис подтверждает перед QA прогоном. Рекомендация относится только к следующему этапу проверки, не к уже выполненной Денисом реализации.

**Area:** frontend адресной формы. **Source:** BUG-013. **Updated:** 2026-09-24, Денис / Developer.

## Goal

Владелец видит и может выбрать первый и остальные варианты улиц.

## Problem

Окно браузера с сохранённым адресом перекрывает первый результат PARROT. Пользователь не понимает, какой список относится к сервису и принят ли адрес.

## Context

[QA BUG-013](../qa/2026-09-24/PARROT669-QA-HOST-2026-09-24.md): есть снимок владельца и анализ текущего поля; независимый повтор с сохранёнными адресами ещё нужен. `autocomplete=off` уже задан. Изменение одного z-index не является доказанным решением для нативного окна браузера.

## Requirements

- Подобрать способ устранить конфликт в воспроизводящем браузерном профиле с сохранёнными адресами.
- Сохранить нормализованный выбор улицы, подписи, клавиатурное и touch-управление.
- Не создавать ложное состояние «адрес выбран» после подстановки браузером обычного текста.
- Проверить создание объекта и изменение адреса. Не менять геопровайдера и модель адреса ради этой UI-задачи.

## Acceptance criteria

- [ ] В воспроизводящем профиле первый результат виден и выбирается мышью.
- [ ] Стрелки/Enter/Escape работают; сохранённый адрес браузера не обходится как подтверждённый нормализованный выбор.
- [ ] Проверены создание и редактирование; сохранение адреса соответствует выбору.
- [ ] Отдельно записаны мобильные результаты либо зависимость от PM-007. Desktop-проверка не закрывает touch.

## Not doing

Требование отключить autofill во всём браузере, замена LocationIQ, карты, публикация точного адреса, общий редизайн.

## Dependencies

Профиль браузера с сохранёнными адресами; актуальное состояние адресного UI. Перед claim сверить работу агента геолокации. Если реальный сценарий блокирует создание объекта, предложить PM повысить приоритет с доказательством.

## Evidence

Исходное доказательство — снимок в QA. Исправление и независимый повтор: не представлены.
