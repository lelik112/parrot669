# PM-007 — Мобильный основной путь

**Title:** проверить поиск, кабинет и контакт при мобильном вводе.

**Status:** blocked — независимый mobile acceptance ждёт управляемый iPhone Safari [PM-015](PM-015-qa-mobile-device-environment.md); доступные браузерные сценарии вынесены в [PM-040](PM-040-playwright-web-e2e.md), нативный остаток — в [PM-041](PM-041-real-device-qa-queue.md). **Priority:** P1. **Owner:** Борис / QA после разблокировки; QA claim на полный прогон нет.

**Agent (ожидаемый):** Борис / QA; claim не подтверждён. **Recommended model:** Luna. **Recommended reasoning:** Medium. **Reason:** проверяется ограниченный перечень мобильных пользовательских путей на фактическом устройстве/браузере; важно точно отметить touch, клавиатуру и эмуляцию.

**Model check:** подтвердить при назначении; эмулятор не выдавать за проверку реального устройства.

**Area:** QA / frontend. **Updated:** 2026-09-24, Марк / PM.

## Goal

Пользователь проходит основные действия с телефона без перекрытых элементов и недоступных действий.

## Problem

Предыдущие desktop-проверки размеров полей и скриншоты не проверяют touch, экранную клавиатуру и мобильные date picker.

## Context

Ограничения [QA 23.09](../qa/2026-09-23/PARROT669-QA-2026-09-23.md) и [QA 24.09](../qa/2026-09-24/PARROT669-QA-HOST-2026-09-24.md). Задача направлена на основной путь, а не на поиск заранее заданного количества багов.

## Requirements

- Записать реальную среду: устройство/браузер, ОС, viewport и наличие touch/экранной клавиатуры. Эмуляцию отмечать отдельно.
- Гость: место/даты → результаты/фильтры → обращение; регистрация/вход по необходимости не теряют контекст.
- Владелец: создать/редактировать тестовый объект, выбрать адрес, указать ночи/цену, закрыть даты; приём сообщений и ответ доступны.
- Проверить переходы списка/диалога, читаемость, горизонтальное переполнение, перекрытия клавиатурой и элементы дат.
- После готовности PM-001 проверить показ задания и Check на телефоне. PM-004 включает браузерный autofill; не дублировать прогон без ссылки на существующее evidence.

## Acceptance criteria

- [ ] Основной путь пройден в заявленной мобильной среде, с конкретными версиями и результатами.
- [ ] Подсказки адреса, даты и отправка доступны при touch; клавиатура не делает нужное действие недостижимым.
- [ ] Ночи и сумма сохраняют правильный смысл; переходы/возврат сохраняют нужный контекст.
- [ ] Приёмка явно разделяет iOS/Android и настоящую среду/эмуляцию; неподдержанная инструментами среда остаётся unverified.
- [ ] Дефекты имеют шаги/результат/evidence и приоритет по влиянию. Отсутствие доступа к мобильному браузеру не выдаётся за дефект приложения.

## Not doing

Обещание поддержки всех устройств, требование найти определённое число багов, полный визуальный редизайн, изменения реальных объектов.

## Dependencies

Для независимого real-device acceptance нужен подтверждённый управляемый iPhone Safari (PM-015/PM-039); для переписки — PM-003. Emulation может дать отдельное evidence по responsive UI, но не закрывает нативные keyboard/date-picker критерии. Владелец уже помогал в одном сценарии PM-001 — это частичное evidence, не доступ Бориса к собственному устройству.

## Evidence

Desktop-измерения из прежнего QA не закрывают эту задачу. Мобильные результаты пока не представлены.
