# PM-005 — Понятный раздел закрытых дат

**Title:** заменить двусмысленный текст и оформление ручных закрытий.

**Status:** planned. **Priority:** P2. **Owner:** не заявлен.

**Area:** frontend кабинета / UX / локализация. **Source:** BUG-014. **Updated:** 2026-09-24, Марк / PM.

## Goal

Владелец сразу понимает, что здесь закрывают ночи для поиска, и не принимает форму за недоступную функцию.

## Problem

«НЕДОСТУПНО · РУЧНЫЕ БЛОКИРОВКИ» в красном оформлении выглядит ошибкой доступа. Текст «Обе даты заблокированы» над пустой формой утверждает ещё не выполненное действие.

## Context

[QA BUG-014](../qa/2026-09-24/PARROT669-QA-HOST-2026-09-24.md). Семантика ночей и работа блокировок уже определены; меняется представление, не диапазоны.

## Requirements

- Нейтральный заголовок **«Закрытые даты»**, без верхнего регистра и оформления ошибки.
- До сохранения объяснять действие: «Укажите ночи, когда жильё недоступно гостям. Они не попадут в поиск; свободные периоды и цены сохранятся».
- Явно показывать включённую последнюю ночь. Сообщение «Даты закрыты для поиска» показывать после успешного сохранения.
- Оформление ошибки использовать для настоящей ошибки. Отличать уже сохранённые закрытия от пустой формы.
- Согласовать смысл EN/ES/CA/RU, не оставлять исправление только на русском.

## Acceptance criteria

- [ ] Пустая форма описывает предстоящее действие и не выглядит отключённой.
- [ ] Заголовок и подписи понятны без объяснения разработчика; последняя ночь явно включается.
- [ ] После сохранения и удаления закрытия видны правильные состояния; покрытие, цены и восстановление доступности не изменились.
- [ ] Все четыре языка согласованы; ошибки остаются видимыми у соответствующего действия.

## Not doing

Изменение правил доступности, интервалов или минимального срока, переработка календарного движка, полный редизайн кабинета.

## Dependencies

Перед claim сверить изменения host UI для PM-001/004. Исполнитель фиксирует область правок, чтобы не перезаписать соседнюю работу.

## Evidence

Исходные текст/снимок в QA; исправление и ретест пока отсутствуют.
