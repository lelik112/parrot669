# PM-045 — пилот пятиминутного пробуждения одного агента

**Title:** проверить, можно ли в авторизованном ChatGPT запустить повторяющийся check-in существующего агентского чата каждые пять минут.
**Status:** closed — пилот с интервалом пять минут не запущен: доступный планировщик ограничивает повторение одним часом; Алексей передал, что Игорь подтвердил невозможность настроить пять минут. Отдельного подтверждения проверки каждого варианта авторизованного UI в репозитории нет. **Priority:** P2 / parked. **Owner:** Марк / Product Manager — фиксирует результат; активного исполнителя и требования действий от Алексея нет.
**Recommended model:** Luna / Low для пустой проверки; Sol / High для разового разбора механизма, только при необходимости.
**Reason:** частые пустые запуски должны стоить как можно меньше; проверить реальные ограничения и расход на одном агенте до распространения.

## Goal

Дать команде проверенный путь «назначение в repo → существующий чат исполнителя просыпается → безопасно читает карточку → один claim → результат» с целевой задержкой до пяти минут без ручного открытия чата владельцем.

## Problem

[PM-043](PM-043-agent-wake-up-feasibility.md) доказала одноразовый scheduled run в существующем чате и GitHub CAS, но доступный callable Automations ограничил повтор не чаще часа. Документация платформы описывает minute intervals; их наличие в авторизованном UI владельца не проверено. Изменения Markdown не являются поддержанным GitHub event trigger; PM-037 касается поиска и к этой работе отношения не имеет.

## Requirements

1. Марк подготавливает краткую инструкцию и ограниченный безвредный пилот для **своего** существующего чата; точный тестовый Assignment ID фиксируется до запуска. Никаких секретов и изменений продукта.
2. В авторизованном ChatGPT UI проверить, предлагает ли расписание каждые пять минут для задачи в этом конкретном чате. Если UI этого не позволяет — записать точный текст ограничения/скрин и остановиться, не подменяя цель часовым polling.
3. Если позволяет, включить короткий пилот на ограниченное время (не более одного дня), с явным способом выключения. Пустой check-in должен читать только одну назначенную тестовую карточку и выходить без записи; когда появляется `assigned`, применять протокол свежего SHA/одного claim из PM-043. Повтор `done`, `blocked` или чужой ID пропускается.
4. Проверить реальные интервалы нескольких запусков, факт возобновления **того же** чата, наличие GitHub read/write и один безвредный assignment → claim. Записать число запусков и фактический расход из доступного usage dashboard; если расход не виден, прямо так и записать.
5. Выключить пилот и подтвердить отсутствие дальнейших запусков. Марк принимает решение: расширить только при доказанной частоте/стоимости, искать иной механизм, либо оставить ручную передачу.

## Acceptance criteria

- [ ] Зафиксировано, доступно ли именно пяти минутное повторение в авторизованном UI и какие шаги требуются владельцу.
- [ ] При доступном расписании несколько реальных runs в одном существующем чате и один безопасный claim подтверждены evidence; повтор не даёт второго claim.
- [ ] Расход/лимит/способ остановки записаны, пилот выключен.
- [ ] Решение о следующем шаге и границы доказанного записаны в PM-045, roadmap и status. Если UI не даёт пять минут, это тоже достаточный итог исследования без ложного PASS.

## Attempt / blocker — 2026-09-26

**Agent:** Марк. **Role:** Product Manager. **Change:** приступил к PM-045 по прямому поручению Алексея. Доступный MCP Automations прямо запрещает повтор чаще раза в час; пять минут через него не создавались. Открыл ChatGPT в отдельном Cloud Browser, увидел гостевой режим. Безопасный auth handoff предложил варианты входа; владелец выбрал Google, переход на Google sign-in состоялся, но подтверждённого входа в ChatGPT пока нет. Поэтому настройки расписания в авторизованном UI не осмотрены, задача остаётся blocked. Никаких повторяющихся задач или расходов не создано.

**Next:** после безопасного входа в этот же Cloud Browser Марк проверяет UI существующего чата и записывает результат. Если UI предлагает 5 минут, сначала согласовать один ограниченный агентский пилот и запустить его с выключением; если не предлагает — отметить критерий как недоступный и отдельно рассмотреть событийный published Workspace Agent. PM-037 к этому не относится.

- 2026-09-26 — **Марк / PM:** после ручной передачи владелец сообщил, что не может печатать в Cloud Browser. Вкладка остаётся на Google identifier без введённых данных; защищённый browserAuth на этом шаге вернул `locator_invalid`. Не просить секреты в чате и не считать auth завершённой. UI пилот ещё blocked; нужен рабочий способ авторизации именно этой сессии либо проверка в собственном авторизованном интерфейсе владельца с зафиксированным evidence.

- 2026-09-26 — **Марк / PM:** скрин владельца из авторизованного раздела «Запланировано» показывает поле текстового запроса и завершённый PM-043 one-shot, но на этом экране нет видимого отдельного переключателя пяти минут или кнопки custom schedule. Предыдущее указание «открыть Custom schedule» для этого экрана было неточным. Дальше проверять через запрос на ограниченную задачу **внутри конкретного чата**, не через рекомендованные standalone задачи. Сам факт доступности пяти минут по этому скрину не установлен.

- 2026-09-26 — **Марк / PM:** исправление после вопроса Алексея: PM-045 моя задача, пилот на моём существующем чате. Прежняя инструкция послать запрос в чат Игоря ошибочна и отменена; Игоря по PM-045 не отвлекать. Авторизованный UI владельца из скрина не показывает отдельный переключатель частоты; callable Automations запрещает чаще часа. Дальше Марк ищет поддерживаемый способ проверки своего чата, а если его нет, фиксирует платформенный блокер без перекладывания работы на Игоря.
