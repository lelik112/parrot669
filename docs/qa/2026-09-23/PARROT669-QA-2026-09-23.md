## BUG-001

**Статус после ретеста 23.09.2026:** Исправлено; независимый production-ретест 23.09.2026 подтверждён.

Следующие шаги и фактическое поведение — историческое описание до исправления.

**Раздел:** Search.

**Серьёзность:** P2 — заметная проблема.

**Название:** Отрицательная верхняя граница цены молча игнорируется.

**Шаги воспроизведения:**

1. Открыть поиск на русском языке.
2. Выбрать Испания → Barcelona, заезд 2026-10-01, выезд 2026-10-08.
3. Оставить «Любой тип», спальни 1+, места 1+, выключить «Только с ценой».
4. Ввести `-100` в «Цена до, €» и нажать «Найти свободное».

**Фактическое поведение:** Значение `-100` остаётся в поле. Ошибки рядом с полем или над результатами нет. Выдаются The therd (€63), One more (€616) и The second (без цены), то есть ограничение фактически не применяется. Для сравнения, значение `100` оставляет The therd, а `0` даёт пустую выдачу.

**Ожидаемое поведение:** Отрицательное значение блокирует поиск с понятной ошибкой «Цена не может быть отрицательной». Пользователь не должен получать выдачу, молча игнорирующую введённое ограничение.

**Почему это важно:** Ошибка ввода выглядит как успешно применённый фильтр; пользователь теряет доверие к поиску.

**Возможное исправление:** Проверять значения цен перед запуском поиска и выводить ошибку у соответствующего поля.

**Доказательство:** [evidence/negative-price.jpg](evidence/negative-price.jpg). Read-only проверка DOM: у поля `min="0"`, `validity.valid=false`, но `form=null`; поисковая кнопка не остановилась на этой невалидности. Это наблюдение DOM, не подтверждённый анализ причины в исходниках.

## BUG-002

**Статус после ретеста 23.09.2026:** Исправлено; независимый production-ретест 23.09.2026 подтверждён.

Следующие шаги и фактическое поведение — историческое описание до исправления.

**Раздел:** Search / UI.

**Серьёзность:** P2 — заметная проблема.

**Название:** Переключение языка не переводит уже загруженные карточки.

**Шаги воспроизведения:**

1. На RU выполнить поиск Испания → Barcelona, 2026-10-01 — 2026-10-08.
2. При желании поставить «Цена до, €» = `100`, чтобы осталась одна карточка.
3. После получения результатов нажать ES.
4. Затем повторить поиск на ES и переключить страницу обратно на RU.

**Фактическое поведение:** Заголовки, фильтры и кнопки переводятся, карточки сохраняют язык последнего поиска. После ES → RU карточка содержит «Habitación privada», «3 dormitorios», «6 plazas», «por 7 noches», «Propietario» внутри русской страницы. Повторное нажатие поиска переводит карточку.

**Ожидаемое поведение:** При выборе языка переводятся и уже показанные результаты без повторного запроса пользователя.

**Почему это важно:** Пользователь переключает язык, чтобы понять условия, но именно условия и данные карточки остаются на другом языке.

**Возможное исправление:** Перерисовывать локализованные подписи карточек и состояние выдачи при смене языка.

**Доказательство:** [evidence/language-cards.jpg](evidence/language-cards.jpg). Подтверждено в обе стороны RU → ES и ES → RU. Само название объекта переводить не требуется.
