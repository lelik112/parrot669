# PM-036 — два аккаунта для Regression QA

**Agent:** Игорь. **Role:** Developer. **Related task:** [PM-036](../tasks/PM-036-regression-qa-independent-two-accounts.md). **Status:** draft; использовать после подтверждения обоих Worker deployments и QA allowlist.

Никита работает со своей парой подтверждённых аккаунтов A (гость) и B (хозяин). Учётные данные получает только защищённым способом; в GitHub и отчёте их не записывать. Борис продолжает использовать свою пару и прежние адреса. Все четыре адреса доступны в одном Chrome без переключения браузерных профилей:

| Участник | Адрес для входа | Ожидаемый аккаунт |
| --- | --- | --- |
| Никита, гость A | `https://parrot669-regression-a.cheltsov112.workers.dev` | отдельный A |
| Никита, хозяин B | `https://parrot669-regression-b.cheltsov112.workers.dev` | отдельный B |
| Борис, гость/хозяин | `https://parrot669.com` и `https://parrot669.cheltsov112.workers.dev` | прежняя пара `qa`/`lelik` |

1. Открыть первый адрес Никиты в одной вкладке, войти под A; во второй вкладке открыть **другой** адрес и войти под B. На каждом адресе через Host/Messages убедиться, что показан нужный аккаунт. При смене аккаунта на том же адресе прежняя вкладка может показывать старое имя до обновления — обновить обе вкладки и сверить личность снова.
2. Под A найти отдельный тестовый объект B, открыть «Написать хозяину» и отправить тестовое сообщение. Под B прочитать и ответить, затем под A увидеть ответ. Не отправлять сообщения на объекты Бориса и не блокировать его тестовый диалог.
3. Обновить обе вкладки: A и B остаются разными. Выйти из A: B должен остаться авторизованным; войти в A снова и повторить проверку. Затем выйти из B и проверить, что A не вышел. Указать фактические HTTP-статусы ошибок доступа, если тест не проходит, без cookies и токенов.
4. Записать в [PM-036](../tasks/PM-036-regression-qa-independent-two-accounts.md) время UTC, браузер, оба адреса, результаты A→B→A, refresh, logout и причину любого расхождения. Smoke Никиты не закрывает критический acceptance Бориса.

При `503 QA site unavailable` не обходить защиту и не входить на адрес Бориса: одному из новых Workers не настроен секрет. При `403` на новом адресе после корректного входа сообщить Игорю о проверке allowlist. При `401` сначала проверить, что на **этом** адресе вообще выполнен вход. Если переключить аккаунт на одном адресе, прежний сеанс другого аккаунта в этом Chrome исчезнет из этой cookie jar; возвращаться нужно через его собственный адрес.
