# PARROT 669 — Rental Verification Checklist v0

Internal checklist for Barcelona rental-verification cases.

## Case setup

- [ ] Assign case ID
- [ ] Record client name/contact
- [ ] Record deadline
- [ ] Record listing URL / source
- [ ] Capture a durable copy of the listing (screenshots/PDF/export) before doing anything else
- [ ] Record property address or best-known location
- [ ] Record advertised rent
- [ ] Record requested deposit / reservation / advance payment
- [ ] Record payment deadline
- [ ] Record person/company requesting payment
- [ ] Record client's specific concern
- [ ] Agree whether physical visit is included

## Evidence intake

- [ ] Save listing/screenshots as evidence
- [ ] Save draft contract, if supplied
- [ ] Save identity documents, if supplied
- [ ] Save property-related documents, if supplied
- [ ] Save payment instructions
- [ ] Save relevant chat/email screenshots
- [ ] Give every evidence item an ID (E01, E02...)

## Property identity

- [ ] Address is present and internally consistent
- [ ] Unit/floor/door details are consistent where available
- [ ] Listing photos/details are compatible with identified property
- [ ] Contract property description matches the claimed property
- [ ] Any reference/cadastral/property identifiers supplied are consistent
- [ ] Material mismatch recorded in report

Status: CONFIRMED / NOT CONFIRMED / INCONSISTENT / NOT CHECKED

## Person / company offering the property

- [ ] Full claimed name recorded
- [ ] Claimed role recorded: owner / agent / representative / other
- [ ] Company/agency details recorded if applicable
- [ ] Evidence supporting claimed role reviewed
- [ ] Name matches relevant documents where expected
- [ ] Contact details are consistent across sources
- [ ] Missing authority/relationship evidence requested if material

Status: CONFIRMED / NOT CONFIRMED / INCONSISTENT / NOT CHECKED

## Contract consistency

- [ ] Parties identified
- [ ] Property identified
- [ ] Rent amount matches agreed/advertised terms
- [ ] Deposit/advance amounts identified
- [ ] Dates and term are internally consistent
- [ ] Payment recipient is identified
- [ ] Names/addresses/account holder details are consistent where expected
- [ ] Obvious blanks, substitutions or conflicting pages recorded
- [ ] Any clause requiring specialist/legal review is flagged as such, not interpreted as legal advice

Status: CONFIRMED / NOT CONFIRMED / INCONSISTENT / NOT CHECKED

## Payment request

- [ ] Amount recorded
- [ ] Recipient name recorded
- [ ] Payment account/details recorded
- [ ] Recipient relationship to claimed landlord/agency explained
- [ ] Payment purpose recorded
- [ ] Timing/urgency recorded
- [ ] Any mismatch between recipient and contract/party recorded
- [ ] Client has not been told by PARROT 669 that payment is "safe"

Status: CONFIRMED / NOT CONFIRMED / INCONSISTENT / NOT CHECKED

## Listing / communication consistency

- [ ] Same property details across listing and messages
- [ ] Same price / deposit across listing and messages
- [ ] Same party/agency identity across sources
- [ ] No unexplained address changes
- [ ] No unexplained bank-recipient changes
- [ ] No contradictory availability/move-in dates
- [ ] Material inconsistencies copied verbatim or summarized precisely

Status: CONFIRMED / NOT CONFIRMED / INCONSISTENT / NOT CHECKED

Notes:

## Physical visit (if included)

- [ ] Visit date/time recorded
- [ ] Exact location reached
- [ ] Exterior/building documented
- [ ] Access obtained / not obtained
- [ ] Unit visited / not visited
- [ ] Photos/videos captured with evidence IDs
- [ ] Visible layout/details compared with listing
- [ ] Material condition differences recorded
- [ ] Person providing access identified by claimed role only unless independently verified
- [ ] No technical/structural safety conclusion given

Status: CONFIRMED / NOT CONFIRMED / INCONSISTENT / NOT CHECKED

Notes:

## Red-flag review

Mark only evidence-based observations.

- [ ] Identity/name mismatch
- [ ] Property/address mismatch
- [ ] Contract/listing mismatch
- [ ] Payment recipient mismatch
- [ ] Unsupported claim of ownership/authority
- [ ] Refusal to provide material supporting evidence
- [ ] Unexplained document alteration/inconsistency
- [ ] Sudden change of payment details
- [ ] Material pressure tied to immediate payment
- [ ] Other documented inconsistency

Details:

## Report QA

- [ ] Every finding has a status
- [ ] Every material finding references evidence
- [ ] "Unknown" facts are not written as facts
- [ ] No "safe / scam-free / guaranteed" wording
- [ ] Legal/technical conclusions are not improvised
- [ ] Important inconsistencies appear near the top
- [ ] Evidence list is complete
- [ ] Limitations are explicit
- [ ] Client-facing report can be understood without internal notes
