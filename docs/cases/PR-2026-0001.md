## 4. Material result of the dry run

The first real process failure happened before any property verification:

**a URL is not sufficient intake evidence.**

A live marketplace page can disappear, change, require browser-side rendering, or block automated retrieval. Therefore PARROT 669 must capture the listing itself at intake.

Required intake artifact from now on:

- screenshots covering the full listing; or
- browser print-to-PDF/export; or
- an internal browser capture performed by PARROT 669 when technically available.

The original URL remains evidence metadata, but not the only copy.

## 6. Product/process lessons

### Lesson 1 — Snapshot first

The checklist now requires a durable copy of every listing before research starts.

### Lesson 2 — Separate source failure from risk

Failure to fetch a page is **not** a red flag against the property. It is only a verification limitation.

### Lesson 3 — Do not substitute "similar" listings

Search engines returned other Barcelona rental pages with overlapping features. None can be used to fill missing facts for listing 186463885.

### Lesson 4 — Intake can be almost frictionless

For a real customer, PARROT 669 does not need a giant questionnaire at the start. A listing link plus a captured copy is enough to begin triage. Missing material can be requested only when the case reaches the relevant check.
