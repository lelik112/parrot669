# D009 — Внешняя ссылка независима от calendar verification

Status: **accepted**. Решение владельца продукта от **2026-09-24**. Записал **Алекс / Strategy**.

## Decision

Валидную Airbnb-ссылку не блокируем из-за отсутствия calendar-control verification.

Если владелец разрешил публикацию внешней ссылки, гость может перейти на Airbnb и сам посмотреть исходное объявление, отзывы и историю. Calendar verification — отдельный trust signal.

Для непроверенного текущего источника гость видит честный статус и, если владелец принимает новые PARROT-сообщения, может попросить его пройти проверку.

## Contract

- Нет внешней ссылки → ссылки нет; объект при подходящей доступности остаётся в поиске.
- Валидная опубликованная ссылка + unverified → ссылка кликабельна; статус: контроль календаря не подтверждён.
- Pending → ссылка кликабельна; статус: проверка не завершена.
- Verified по D002 → ссылка кликабельна; можно показывать «Контроль календаря подтверждён».
- Failed / blocked / expired / lost → ссылка кликабельна, если URL валиден и опубликован; verified-сигнал не показывается.
- Legacy v1 verified не считается D002 verification.
- Невалидная / mismatched ссылка публично не показывается.
- Замена источника снимает verification прежнего источника; новый валидный URL может быть публичным как unverified.
- Удаление ссылки убирает публичный переход.
- Disable/enable синхронизации само по себе не меняет verification.
- Search и будущий public host profile используют один и тот же смысл.

## Ask host to verify

Для unverified/pending/lost состояния дать действие **«Попросить владельца подтвердить календарь»**, когда существующий messaging flow разрешает новое обращение.

Действие не должно скрыто отправлять сообщение. Допустим переход в диалог с подготовленным текстом.

Если владелец не принимает новые обращения, отсутствие этого действия не блокирует Airbnb-переход.

## Reason

PARROT должен показывать, что именно проверено, а не прятать полезный внешний источник. Ссылка даёт внешний контекст и репутацию Airbnb; verification подтверждает только контроль календарного источника.

## Rejected

- Блокировать Airbnb-ссылку до verification.
- Автоматически публиковать ссылку как следствие verification.
- Использовать vague label вроде `Trusted host`.
