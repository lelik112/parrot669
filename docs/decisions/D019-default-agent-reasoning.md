# D019 — дефолтная модель и уровень для агентов

**Decision:** Для рабочих чатов PARROT целевая модель — Sol. Уровни reasoning считаем по порядку от 1 до 6; меньший номер означает меньшую мощность. Целевые настройки: Марк 4/6, Денис 4/6, Игорь 4/6, Борис 4/6, Никита 3/6, Алекс 4/6. Алекс остаётся вне адресного rollout по своей просьбе. Эти значения действуют как рабочая база **после однократной ручной настройки Алексеем**; PM не может поменять настройки чужих чатов инструментом. Пока подтверждения настройки нет, не выдавать таблицу за проверенные текущие значения.

Адресный комментарий будит агента как обычно. Перед основной работой агент сам сверяет требования своей части задачи с подтверждённым дефолтом и делает Model check. Если мощности хватает, он подписывает claim и продолжает; рекомендация ниже дефолта не требует переключения. Если нужен уровень выше или модель мощнее Sol, агент записывает обоснованный блокер в карточке и передаёт Марку через PR #60 без старта зависимой работы. Марк сообщает Алексею, какую настройку и зачем нужно повысить. После подтверждения изменения Марк новым адресным комментарием будит агента для повторного Model check и продолжения. Уже начатая работа продолжается; если недостаточность выявлена позже, агент останавливает только зависимую часть по тому же порядку.

**Problem:** Частые ручные переключения между задачами мешают работе. Рекомендация в карточке сама по себе не показывает, хватает ли подтверждённого дефолта конкретному исполнителю.

**Reason:** Запас 4/6 покрывает обычные сложные PM, developer и acceptance задачи; 3/6 покрывает повторяемый regression QA Никиты. Повышение до 5/6 или 6/6 остаётся редким явным решением владельца. Система не заявляет, что настройка фактически применена, пока Алексей её не подтвердил.

**Alternatives:** Подбирать уровень под каждую задачу; назначить всем максимум 6/6; оставить только рекомендации в карточках без дефолтов.

**Rejected:** Автоматически менять настройки чужих чатов, молча понижать уровень ради простой задачи, продолжать зависимую работу после обоснованного запроса повышения до решения владельца, считать комментарий claim без подписанной записи.
