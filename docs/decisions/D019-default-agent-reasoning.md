# D019 — дефолтная модель и уровень для агентов

**Decision:** Для рабочих чатов PARROT целевая модель — Sol. Уровни reasoning считаем по порядку от 1 до 6; меньший номер означает меньшую мощность. Целевые настройки: Марк 4/6, Денис 4/6, Игорь 4/6, Борис 4/6, Никита 3/6, Алекс 4/6. Алекс остаётся вне адресного rollout по своей просьбе. Эти значения действуют как рабочая база **после однократной ручной настройки Алексеем**; PM не может поменять настройки чужих чатов инструментом. Пока подтверждения настройки нет, не выдавать таблицу за проверенные текущие значения.

Перед отправкой адресного комментария, запускающего новую задачу в чате агента, отправитель сравнивает рекомендованную модель и уровень *для этапа адресата* с подтверждённым дефолтом. Если требуется уровень выше или модель мощнее Sol, Марк кратко объясняет Алексею почему и какое значение выставить; адресата будят только после подтверждения изменения. Рекомендация ниже дефолта не требует переключения: агент работает на текущей настройке. Уже начатая работа не прерывается этим решением. Если агент обнаружил недостаточность после claim, он останавливает зависимую часть, фиксирует причину и запрашивает повышение через Марка.

**Problem:** Частые ручные переключения между задачами мешают работе. Без проверки до PR comment агент может проснуться на задачу, для которой текущая настройка недостаточна.

**Reason:** Запас 4/6 покрывает обычные сложные PM, developer и acceptance задачи; 3/6 покрывает повторяемый regression QA Никиты. Повышение до 5/6 или 6/6 остаётся редким явным решением владельца. Система не заявляет, что настройка фактически применена, пока Алексей её не подтвердил.

**Alternatives:** Подбирать уровень под каждую задачу; назначить всем максимум 6/6; оставить только рекомендации в карточках без дефолтов.

**Rejected:** Автоматически менять настройки чужих чатов, молча понижать уровень ради простой задачи, будить агента на новую задачу выше подтверждённого дефолта до решения владельца, считать комментарий claim без подписанной записи.
