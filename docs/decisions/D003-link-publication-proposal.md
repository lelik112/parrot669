# D003 — Публикация ссылки после проверки источника

Status: **superseded — не было принято; заменено D009**. Автор: **Марк / PM**.

**Decision:** предложение — показывать ссылку Airbnb гостю только после успешной проверки текущего источника и разрешения владельца. Рекомендация PM: после успеха галка становится доступной, но остаётся выключенной до отдельного действия.

**Problem:** сейчас `showInSearch` включается при добавлении listing и не зависит от проверки. Владелец выразил ожидание, что до проверки включить галку нельзя. В основном контексте пока описано прежнее независимое правило.

**Reason:** связать публикацию с понятным сигналом и сохранить управление показом у владельца. Это изменение продуктового правила, не исправление нарушения старой спецификации.

**Alternatives:** сохранить независимость; автоматически показывать ссылку после успеха; требовать отдельную галку после успеха. По последнему выбору вопрос владельцу задан, ответ ещё не получен.

**Rejected:** окончательное отклонение этих вариантов пока не зафиксировано. Исключать весь объект из поиска противоречит D000; одного disabled-переключателя недостаточно для соблюдения любого выбранного серверного правила.

**Date:** предложение зафиксировано 2026-09-24; дата принятия отсутствует.

**Source:** [QA PRODUCT-001](../qa/2026-09-24/PARROT669-QA-HOST-2026-09-24.md), действующий product-context и вопрос PM владельцу.

**Task:** [PM-002](../tasks/PM-002-link-publication.md).

## Требуется решить

1. После успеха — автоматическая публикация или отдельная галка? Рекомендация PM — отдельная галка.
2. Старые v1 `verified` не доказывали выполнение задания D002. Рекомендация PM — не применять к ним новый смысл без повторной проверки; точную переходную политику записать до выпуска.
3. Что происходит с уже опубликованными ссылками без подходящего подтверждения? Рекомендация PM — скрыть ссылку с объяснением владельцу, сохранив участие объекта в поиске.
4. Какие публичные поверхности ограничивает правило? Поиск и публичный профиль сейчас имеют разные правила. Явно выбрать область; не оставлять случайный обход через другую страницу.
5. Замена/удаление источника снимает подтверждение. Обычный disable/enable синхронизации сейчас сохраняет verified; не менять это правило молча.

Реализация PM-002 остаётся blocked до фиксации полного контракта. Обсуждение и техническая оценка разрешены; предложение нельзя публиковать как уже принятое поведение.
