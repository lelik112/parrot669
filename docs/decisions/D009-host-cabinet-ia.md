# D009 — Минимальная информационная архитектура кабинета

**Status:** proposed — продуктовый контракт подготовлен, ожидает подтверждения Алексея.
**Decision:** предложение — оставить текущие публичные маршруты Search / Host / Messages. На /host.html владелец работает с объектами; доступность и iCal находятся внутри карточки конкретного объекта; настройка новых обращений остаётся настройкой владельца; переписка и ответы находятся в Messages. Account ограничен входом/регистрацией, идентификатором учётной записи, выходом и восстановлением. Отдельный Dashboard не создаётся до появления полезных и проверяемых показателей. Profile не показывается в первой версии; личные/публичные данные остаются отдельными задачами PM-021/022.

**Problem:** предложение о шести разделах кабинета смешивает имеющиеся инструменты и ещё не принятые профиль/метрики. Повторная навигация и пустые вкладки увеличат объём MVP и могут отвлечь от пути «объект → доступность → контакт».

**Reason:** действующие действия уже сгруппированы по объекту, а входящие диалоги отделены в Messages. Владелец управляет доступностью каждого объекта отдельно; пустой аккаунт можно направить к созданию первого объекта. Существующие URLs сохраняются.

**Alternatives:** оставить текущую верхнюю навигацию без изменений; добавить вкладки Properties / Availability / Contacts / Profile / Account; сохранить Search / Host / Messages, а внутри Host показать только Properties и контекстное управление датами. Рекомендация PM — последний вариант, минимально меняющий рабочий путь.

**Rejected:** пустые Dashboard/Profile; отдельная глобальная Availability для нескольких объектов, когда даты задаются внутри каждого; отдельная Contacts-вкладка без самостоятельной функции; смешение Account и профиля хозяина; изменение видимости Airbnb-ссылки в этой задаче.
