# D009 — Минимальная информационная архитектура кабинета

**Status:** accepted — подтверждено владельцем продукта 2026-09-24.
**Decision:** оставить текущие публичные маршруты Search / Host / Messages. На /host.html владелец работает с объектами; доступность и iCal находятся внутри карточки конкретного объекта; настройка новых обращений остаётся настройкой владельца; переписка и ответы находятся в Messages. Account ограничен входом/регистрацией, идентификатором учётной записи, выходом и восстановлением. Отдельный Dashboard не создаётся до появления полезных и проверяемых показателей. PM-020 реализует навигацию существующего кабинета; **PM-021 (private host profile) идёт следующим этапом после PM-020**, без ожидания пилота; **PM-022 (public host profile) идёт после PM-021**. Profile не обязан становиться новой верхней вкладкой на этапе PM-020, но сама профильная область является следующим запланированным этапом, а не неопределённым LATER.

**Problem:** предложение о шести разделах кабинета смешивает имеющиеся инструменты и ещё не принятые профиль/метрики. Повторная навигация и пустые вкладки увеличат объём MVP и могут отвлечь от пути «объект → доступность → контакт».

**Reason:** действующие действия уже сгруппированы по объекту, а входящие диалоги отделены в Messages. Владелец управляет доступностью каждого объекта отдельно; пустой аккаунт можно направить к созданию первого объекта. Существующие URLs сохраняются.

**Alternatives:** оставить текущую верхнюю навигацию без изменений; добавить вкладки Properties / Availability / Contacts / Profile / Account; сохранить Search / Host / Messages, а внутри Host показать только Properties и контекстное управление датами. Рекомендация PM — последний вариант, минимально меняющий рабочий путь.

**Rejected:** пустой Dashboard; пустая Profile-вкладка до реализации PM-021; отдельная глобальная Availability для нескольких объектов, когда даты задаются внутри каждого; отдельная Contacts-вкладка без самостоятельной функции; смешение Account и профиля хозяина; ожидание пилота как блокер для самого private Profile; изменение видимости Airbnb-ссылки в этой задаче.

**Approved:** Алексей подтвердил D009 2026-09-24 с уточнением последовательности: PM-020 → PM-021 → PM-022. PM-021 не блокируется PM-008/pilot; пилот может повлиять на дополнительные поля, но не на сам факт отдельного private Profile.
