# D017 — адресные PR inbox для существующих чатов

**Decision:** Для команды PARROT использовать один открытый docs-only draft PR на каждого AI-агента как адрес GitHub comment events. PM сначала фиксирует задачу в карточке на `main`, затем оставляет адресный комментарий в PR исполнителя; по завершении исполнитель отправляет handoff в PR Марка #60. Каждый агент один раз включает `pull_request` trigger с `enable_comments=true` и фильтром по **своему PR** внутри своего существующего чата. PR сам по себе не включает trigger и не означает, что сообщение прочитано.

**Problem:** Алексей вручную переносит назначения и результаты между чатами; обычный push Markdown на `main` не запускает текущие чаты.

**Reason:** PM-046 подтвердил PR comment → прежний чат Игоря (#61), ответный comment → прежний чат Марка (#60), затем второй отдельный comment → тот же чат Игоря. Адресный PR позволяет передавать работу через репозиторий без нового агента и отдельного PR на каждое назначение. Карточка остаётся источником scope, claim, QA и статуса. Для нового сообщения нужны точные строки `To:`, уникальный `Wake ID:` и `Related task:`; обработчик перечитывает карточку, подписывает результат и не дублирует собственный обработанный ID.

**Alternatives:** Отдельный PR на каждое назначение (много веток и CI-шум); почасовой polling (задержка, не запускает остальные чаты); один общий PR на всю команду (все настроенные чаты получают каждый comment event и тратят runs на чужие сообщения); ручная передача Алексеем.

**Rejected:** Автоматический claim только по тексту комментария; расширение scope без карточки; merge рабочих inbox PR; новые репозитории, GitHub Actions, секреты, пятиминутный scheduler и новый агент ради маршрутизации. Shared GitHub login не удостоверяет автора сообщения.

**Date:** 2026-09-26.

**Status:** accepted для ограниченного командного внедрения по прямому поручению Алексея. [Марк #60](https://github.com/lelik112/parrot669/pull/60) и [Игорь #61](https://github.com/lelik112/parrot669/pull/61) имеют подтверждённый однократный двусторонний handoff; второй уникальный event разбудил Игоря. [Денис #62](https://github.com/lelik112/parrot669/pull/62) и [Борис #63](https://github.com/lelik112/parrot669/pull/63) также `active`: личные triggers и один сквозной тест с signed receipt подтверждены. [Никита #64](https://github.com/lelik112/parrot669/pull/64) включил trigger и сам запросил тест, но остаётся `prepared` до receipt; [Алекс #65](https://github.com/lelik112/parrot669/pull/65) `prepared`, его просьба не беспокоить сохраняется. Из чата Марка нельзя привязать automation к другим существующим чатам: доступный create не принимает target conversation ID. Каждый адресат делает однократную настройку в своём чате; после неё Марк посылает тест только по согласованному setup и фиксирует результат. Дубликат одного event и регулярная денежная/CI стоимость ещё не измерены.

**Related task:** [PM-046](../tasks/PM-046-github-event-existing-chat-wakeup.md). **Agent:** Марк. **Role:** Product Manager. **Change:** зафиксирован принятый адресный процесс и граница подтверждённых inbox.
