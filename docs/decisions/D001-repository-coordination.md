# D001 — Координация команды через репозиторий

Status: **accepted**. Автор записи: **Марк / PM**.

**Decision:** продуктовая работа и коммуникация команды ведутся в документах `lelik112/parrot669`, общих для frontend и backend. Постоянные задачи находятся в `docs/tasks/`, решения — в `docs/decisions/`, приоритеты — в roadmap, актуальная сводка — в status.

**Problem:** история и поручения разбросаны по чатам; общий GitHub-аккаунт не показывает, какой агент отвечает за работу. Пользователь вынужден переносить сообщения между участниками.

**Reason:** владелец поручил организовать работу через репозиторий и дал PM право изменять продуктовые документы. Один ответственный, подписанные записи и связанные доказательства позволяют продолжать работу после потери контекста и обнаруживать пересечения.

**Alternatives:** продолжать передавать задачи копированием промптов; вести независимые backlog в обоих репозиториях; вводить дополнительный трекер. Это варианты оценки PM, а не утверждение о состоявшемся обсуждении команды.

**Rejected:** дублировать одну задачу между двумя списками; считать обновление файла доставленным поручением без подтверждения агента; назначать себя исполнителем чужой уже взятой задачи; менять код или инфраструктуру от роли PM.

**Date:** 2026-09-24.

**Source:** прямое поручение владельца о работе через репозиторий и новая роль PM. Отдельное требование `docs/status.md` дополняет перечисленный список разрешённых документов.

**Implementation:** [правила, роли, авторство и индекс](../tasks/README.md). Имена: Марк — PM, Алекс — стратег без доступа к инструментам; имена разработчиков и QA ожидаются. Работа с общим аккаунтом не выдаётся за наличие отдельных GitHub-аккаунтов.

**Success criteria:** у начатой задачи есть именованный ответственный, понятный следующий шаг, история вопросов/ответов и ссылка на результат; другой агент может продолжить по репозиторию без восстановления всего чата. Не обещается автоматический запуск или фоновое чтение задач.
