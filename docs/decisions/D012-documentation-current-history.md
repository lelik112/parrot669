# D012 — Текущее состояние отдельно от журналов документации

**Status:** accepted — прямое решение Алексея от 2026-09-25 («предложения по PM-035 полностью принимаются. Реализовывай»).
**Agent:** Марк. **Role:** Product Manager. **Related task:** [PM-035](../tasks/PM-035-documentation-structure-refactoring.md). Дополняет [D001](D001-repository-coordination.md), не меняя продуктовых правил.

## Decision

- `docs/tasks/README.md` остаётся **коротким индексом**; требования и текущий статус — в карточке задачи, единые правила claim/handoff — в [workflow](../tasks/workflow.md). Исходное содержимое README сохранено [дословным снимком](../tasks/README-history-2026-09-25.md).
- `docs/team-chat.md` остаётся **стабильной входной ссылкой** на [дневные логи](../team-chat.md). Вчерашний разговор открывается из архива, новые сообщения пишутся в лог текущей даты UTC. Свободное общение и критика руководства сохраняются без требования task ID.
- Для длинной активной задачи допустим `docs/tasks/logs/PM-XXX.md`: история событий там, а текущие статус, owner, критерии и следующий шаг — в карточке. [PM-030](../tasks/PM-030-qa-drain-next-stage.md) — первый пилот; перенос PM-001/029 во время QA не требуется.
- При восстановлении сначала читаются статус, короткий индекс, своя карточка и новые адресованные сообщения; релевантные разделы product-context, решения и changelog открываются для принятия решения/проверки истории. Исходные архивы доступны, но не читаются целиком по умолчанию.

## Problem

Длинные индекс, курилка и changelog смешивали текущую работу с архивом и требовали больших повторных чтений при каждой потере сессии. Обновление общего файла увеличивало риск конфликта записей.

## Reason

Меньше обязательных для чтения страниц и сохранённые прямые входы ускоряют восстановление агента. Карточка остаётся одним источником актуального статуса; историю и авторство можно проверить по датированным логам и исходному Git-снимку.

## Alternatives

- Оставить текущие крупные файлы и просто попросить агентов читать только начало.
- Создать отдельные backlog, archive и history как три параллельных реестра.
- Разбить сразу все существующие карточки и весь product-context.

## Rejected

- Удалять старые сообщения, отчёты QA и авторство.
- Дублировать статус задачи в отдельном независимом backlog.
- Переносить PM-001/029 во время активной приёмки или менять критерии/продуктовую логику ради уборки docs.
- Заставлять команду читать весь архив курилки и changelog при каждом старте.
